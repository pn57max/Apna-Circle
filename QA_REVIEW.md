# Apna Circle — Product Owner and QA Review
Date: 2026-11-10
Build: Reviewed local HTML/JS prototype, revised in this package.

## Verified checks
- Node.js `--check` on extracted application JavaScript: PASS.
- Static assertions for map/filter rendering, calendar integration, feed loader, capacity guard and navigation scope: PASS.
- Browser interaction, external image availability, remote map tiles, calendar provider behavior, WCAG audit, and end-to-end backend flows: NOT TESTED.

## Fixed in this revision
- P1: Navigation hid unrelated homepage storytelling sections when switching tabs; scoped tab visibility to top-level routed sections and separately handled decorative sections.
- P1: Fixed sample activity dates that would become stale; demo fixtures now use rolling future dates. Existing browser demo data resets to a new v2 local storage key; no production data involved.
- P1: Join requests could exceed advertised capacity; added a local capacity guard and disabled full-activity join actions.
- P2: Community filtering previously included all Mixed / Everyone listings when a specific community was selected; now matches the selected tag exactly.
- P2: Calendar end-time arithmetic depended on local machine timezone; now calculates a floating wall-clock hour consistently. This is NOT a substitute for authoritative event start/end times and correct timezone normalization.
- P2: Clarified demo data and one-hour calendar assumption.

## Open issues and release blockers
- P0: No authentication, backend persistence, moderation, or actual host notification/approval; localStorage is not suitable for production.
- P0: Trust and safety workflows (report/block, consent, verified attendance) are absent.
- P1: No verified public calendar connectors; events.json is empty and external events require geocoded data.
- P1: Costco/store coordinates and some venues are illustrative, not verified; directions may be inaccurate.
- P1: External event IDs are generated by array index and not stable across feed refreshes.
- P1: Calendar assumes one-hour duration; .ics interoperability and DST transitions require cross-client tests.
- P1: No automated browser tests or responsive/accessibility audit yet.
- P2: External stock images and CDN dependencies can fail or change; use approved hosted assets and fallbacks.
- P2: Admin dashboard numbers are demo counts and should not be treated as user analytics.

## Release verdict
NOT READY FOR PUBLIC LAUNCH. Suitable for stakeholder demonstration with clearly labeled sample data.
